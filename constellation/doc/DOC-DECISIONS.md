# Decision Log (index)

Running log of architectural decisions. **Each decision is a DECISION card** —
the cards carry the full Context / Decision / Alternatives / Consequences;
this index maps the historical D-numbers to them. Append new decisions as new
`DECISION-D<nn>-…` cards with the next number and add them here. Do not
renumber or delete entries; mark superseded decisions with the `supersedes`
field on the successor card.

[[DOC-SPEC]] is the enforceable contract; the decision cards record **why**.

## Founding & v1 contract

- **D99** [[DECISION-D99-SKILL-REFRESH-PROMPT]] — `puzzle add skills` asks instead of refusing, and gains `puzzle upgrade skills`: because the payload is `go:embed`-ed, re-running `add skills` after an upgrade IS the refresh mechanism, and it was the one path that answered with an error (an all-or-nothing pre-flight inherited from `add piece`, where the files being protected are hand-authored — a skill directory is generated content the user never writes). Every install now stamps `<dest>/.puzzle-skill-version` with the CLI version, turning staleness from an inference into a fact (missing/blank reads as *unknown*, never an error, so pre-D99 installs sort with stale); selected targets classify missing → install, stamp-matches → skip as up to date, stale/unstamped → confirm, symlink → report and skip. **Declining skips only the conflicts** — the pre-flight was all-or-nothing because it produced an *error*, and "no" about `~/.codex` says nothing about a `~/.cursor` with no skill to protect. Symlinked destinations are never offered (D97's dev-checkout rule, now applied to `add`, so a routine "yes" cannot revert someone's working tree) but `--overwrite` still writes through, since D97's re-exec depends on that shape. Non-TTY keeps the refusal verbatim, except that an up-to-date install is no longer a conflict — making `add skills` idempotent in CI. `puzzle upgrade skills` installs from THIS binary with no registry check and no re-exec — the mirror image of D97, which must re-exec precisely because its process holds the OLD payload — refreshes only existing installs, and installs on a non-TTY without prompting because the command names the clobber. Abort-on-decline, prompting for symlinks, never writing through a symlink even with `--overwrite`, reading `SKILL.md`'s hand-maintained frontmatter version instead of a stamp, an `upgrade --skills` flag, and routing the subcommand through `runUpgrade` all rejected (v1.62 → SPEC §13/§41)

- **D110** [[DECISION-D110-DEV-PROXY-PREFIX-VALIDATION]] — `dev.proxy` rejects a `/` prefix (a root proxy leaves the dev server nothing of its own to serve; the feature's shape is "carve out the paths the backend owns") and rejects two prefixes that normalize to the same route after trailing-slash trimming (which previously panicked `ServeMux` and killed `puzzle dev` with a Go stack trace); both validate in `config.validate` alongside the existing leading-slash and target-URL rules, so `puzzle build` rejects them too, and the `handler()` guards stay as defense in depth because `Serve` is fail-soft on config errors; silent normalization and dev-path-only enforcement rejected (removes documented `/` behavior, unpublished)

- **D111** [[DECISION-D111-MANAGED-HEAD-BUILD-TIME-ONLY]] — managed head tags (`og:*`/`twitter:*`/`canonical`) become build-time only: the runtime `syncTags` and its router call site are deleted, and with them `__PUZZLE_HAS_HEAD_TAGS__`, its whole-project byte scan, `Usage.HasHeadTags`, and the watch-rebuild invalidation; crawlers always GET each URL fresh and never client-navigate, so the SSG's per-page baked tags are the only copy anyone reads, and a SPA (app software behind auth — banking, design tools, kanban) has no crawler to serve; `syncTitle` stays ungated so the browser tab title still updates everywhere; deleting the one router import leaves `syncTags` with no browser importer, so plain tree-shaking replaces the whole gate; `ScanUsage` now reads only `.pzl`; amends [[DECISION-D89-FEATURE-USAGE-TREESHAKE]] (its `flip` half stands), supersedes the same-day `title`-probe patch; `meta.description`/`canonical`/`socialImage` are dead config under `output: 'spa'` by choice

- **D112** [[DECISION-D112-STORE-ID-KEY-NORMALIZATION]] — record identity is number/string-insensitive: one `recordKey` helper (numbers → their string form, everything else untouched) at every id-keyed record-Map access and on both sides of `hasMany`'s FK filter, because subscription keys and adapter URLs already string-coerce — the Map was the store's only type-sensitive identity, so `findOne('post', this.params.id)` (route params are strings) subscribed to the right key yet missed a record a numeric-id JSON payload created, returning `null` while reactivity looked healthy; `save()`'s `pkDiffers` compares under the same rule, so a server echoing numeric `1` for a record keyed `'1'` merges normally instead of warning/adopting; record fields never coerce (a numeric server id stays a number), `null`/objects keep SameValueZero, no numeric parsing (`'01'` ≠ `1`); duplicate detection unifies — a type-variant duplicate now throws/updates in place instead of silently creating the shadow record that WAS the corruption; schema-driven coercion rejected (schemas optional → two identity regimes; the exempt server paths can hold ids the schema disagrees with; `Number()` is lossy — `''`→`0`, `NaN`, >2^53 snowflake ids) (SPEC §8/§21)

- **D113** [[DECISION-D113-SSG-RAWTEXT-RULE]] — prerender RAWTEXT rule: the SSG serializer stops entity-escaping `<script>`/`<style>` text (RAWTEXT is never entity-decoded, so escaping corrupted prerendered JSON-LD into `&amp;` garbage for exactly the crawlers D111 says are the only readers, and killed `a > b` selectors in `<style>`) — JSON-typed scripts (`application/json` or any `+json` suffix) emit raw with `<` → `\u003c`, the SAME escape the D81 static data island already used, now shared as one `escapeScriptJson` helper; all other script/style content emits raw behind a build error on `</script`/`</style` (case-insensitive) or the `<!--`+`<script` double-escaped pair, because raw-always is a stored-XSS breakout (RAWTEXT ends at the first `</script`, even mid-string) and the serializer cannot know the embedded language's string semantics well enough to auto-repair; build-output-only change, no runtime bytes; entity-escaping (the bug), raw-always, auto-`<\/script` repair, and banning RAWTEXT interpolation all rejected (SPEC §36)

- **D114** [[DECISION-D114-CALENDAR-DATE-FORMATTERS]] — a bare `YYYY-MM-DD` is a calendar date: `date`/`time`/`datetime`/`timeago` parse it as LOCAL midnight via one shared `parseDateInput` helper, and `in_timezone` passes it through UNSHIFTED — a day names no instant to re-express, and shifting from any midnight anchor renders viewer-dependently (the ES spec parses date-only forms as UTC midnight while Intl renders local, so `"2026-07-24"` displayed as 07/23/2026 west of UTC — quiet, data-shaped, exactly what JSON APIs and `<input type="date">` produce, invisible to anyone testing east of UTC), with a round-trip check coercing rollover components to Invalid Date so they fail soft to the raw string (`"2026-02-31"` is spec-LEGAL — DD ≤ 31 — and previously rolled into March TZ-dependently, while `"2026-13-01"` fails the grammar; coercion makes a nonexistent day behave like a nonexistent month); the `iso` preset is idempotent on calendar dates (`'2026-07-24'` out, not a TZ-dependent `T00:00:00.000Z` instant); Date instances/timestamps/full ISO datetimes byte-identical; strict match only (no trim, no single-digit forms); formatting-in-UTC-instead (leaves the parsed instant wrong for `timeago`/chained math), an opt-in `utc` flag (the default is the bug), and app-zone config (a different feature) all rejected (SPEC §6)

- **D115** [[DECISION-D115-MOUNT-FAILURE-RECOVERY-CONTRACT]] — the failed-first-mount teardown recovers through the INSTANCE both vnode generations share, not the mount-time vnode: the rejection handler runs in a microtask, so a same-turn parent re-render can already have transferred the instance to a new vnode (`patchComponent`), and nulling the orphan's links recovered nothing — the live vnode kept a destroyed instance forever (permanently blank component + orphaned `<!--puzzle-->`), the exact failure the teardown was written to prevent; the handler stashes its placeholder on the instance (`__failedPlaceholder`), `patch()` recovers on `component == null || component.isDestroyed` (the getter — `destroyed` is the always-truthy hook METHOD) with an attached-only insertion-ref guard, and the whole teardown is gated `if (!preloaded)` — a Router-adopted view's lifetime belongs to the Router, whose post-commit contract expects a failed committed view to stand until the next navigation replaces it

- **D116** [[DECISION-D116-PACK-TIME-PIN-INJECTION]] — the four platform optionalDependencies are injected into package.json at pack time (prepack) and removed after (postpack), never tracked (pins sitting between a version bump and the publish desync package-lock.json against unpublished versions and break `npm ci`); verify-pack packs a REAL tarball and asserts the pins out of `package/package.json` plus the file list out of `tar -tzf` — the prior check validated `injectPins()` against itself (the function under test as its own oracle) and printed PASS under every hook-skipping publish path (`--ignore-scripts`, a republished tarball, a failed prepack), which would have shipped a manifest installing no platform binary; after packing it asserts the working-tree AND committed (HEAD) manifests are pin-free again (npm skips postpack when the pack step fails, so `release:prep` also restores as its step 0); packing from a staged copy deferred as a tooling rewrite

- **D118** [[DECISION-D118-LIFECYCLE-HOOK-CONTAINMENT]] — user lifecycle hook errors are contained at every boundary with the framework's existing logged/never-wedges posture, and mount cycles carry a generation token: `destroyed()` is guarded (the last unguarded teardown-path hook — a throw escaped through the parent's `#vm.clear()` cascade, `Router.stop()`, and `PuzzleApp.#teardown()`, stranding `_mounted` true so a later `mount()` silently no-op'd); the visible-trigger reveal guards `viewWillShow`/`viewDidShow` and guarantees `handle.play()` + `#settleEnter()` (an unguarded throw left the paused enter holding content at opacity-0 forever with `playIn()` never settling — the §39 never-stranded rule violated from inside, invisible to callers because the reveal fires from an IntersectionObserver delivery); `render()` → null clears AND re-anchors (bare `clear()` nulls `element` and a later render appends among siblings); devstate notifies the D100 observer only when the registry delete removed something (balanced pairs); and `PuzzleApp.#mountEpoch` makes every post-await mount continuation prove it still owns the app — the `_mounted` boolean cannot distinguish "my mount is live" from "a newer mount claimed the flag", so unmount+remount during an awaited `beforeMount`/`router.start()` double-started the router, double-fired `mounted`, or tore down the healthy replacement cycle from the stale abort path (SPEC §12/§34/§39)

- **D119** [[DECISION-D119-ROUTER-SETTLEMENT-ANNOUNCEMENT]] — two router edge fixes: the in-flight same-path double-click guard returns the in-flight navigation's PROMISE (`#pendingNavPromise`, paired with `#pendingNavPath` at every set/clear point) instead of a fresh `Promise.resolve()`, so a second `await router.push(p)` settles when that navigation commits/fails/supersedes rather than while the old route is still mounted (the committed-same-path guard keeps its immediate resolve — that navigation already happened); and `#announceRoute` announces `document.title` only when non-empty and actually moved since the last announcement (tracked via `#announcedTitle`, seeded with the pre-nav-#0 title), else falls back to the committed route's `name` then `path` — aria-live announces on change only, so the unchanged-title write was silent in no-title apps and named the departed page in mixed ones (amends D93 / SPEC §51)

- **D120** [[DECISION-D120-TARBALL-PUBLISH]] — the root package is published as a packed tarball (`npm publish ./magic-spells-puzzle-<version>.tgz`), never from the repo directory: `npm publish` on a directory packs (firing D116's `prepack` inject / `postpack` restore) and then **re-reads `package.json` from disk** to build the registry metadata, by which point postpack has stripped the pins — so the tarball ships pin-perfect while the packument declares no `optionalDependencies`, and npm resolves installs from the packument. 0.3.0 shipped exactly that way (`puzzle --version` → "no prebuilt CLI binary available for this platform" on every machine) and cannot be repaired in place; every pipeline check passed because every check inspected the tarball.
