# ViewManager DOM patching, events, and bindings

The node-level contract of [[COMPONENT-VIEW-MANAGER]]: what the patcher does to
real DOM, and what it promises not to touch. Suites under `tests/` include
`vdom*`, `patch-*`, `keyed-reconciliation`, `list-*`, `static-cache*`,
`component-prop-bailout`, `dom-islands`, `inline-svg`, `event-*`,
`outside-modifier`, `binding`, `bind-plain-object-containment`,
`mount-*`/`first-mount-throw`, and `virtual-scroll-example`.

- mount and patch of attributes, properties and children; form values set as
  properties; controlled `select` values; conditional-arity placeholder padding so
  trailing siblings keep their slots.
- keyed reconciliation on `(tag, key)` pairs, auto-key resolution including
  custom primary keys, and the null-key warning; D170 list blocks and static
  subtree caching, including control-value replay into cached rows.
- the component prop bailout — the shallow-equality boundary that decides
  whether a child re-renders at all.
- `component-slot` (D180): stable comment-bracketed positions for empty/selected output, keyed moves of whole ranges through component roots, compiled conditional replacements before the leaving selected element with the same order as plain components, recursive nested component-root range ends and unknown-tree recovery; current props/events through the ordinary selected component path, and immediate cleanup on constructor changes. A compiled-out feature diagnostic names `<Component>` and its own build gate.
- `island` freezing children after mount while its own attrs and listeners keep
  patching; inline SVG arriving as string children.
- per-node listeners, `@event` modifiers, key filters, and the `outside`
  modifier with its portal awareness. `event-key-filters-parity` pins the runtime
  key-filter table to the compiler's — adding a filter on one side alone fails.
- implicit two-way binding across its arms (local state, record, plain object,
  primitive bind root), the coercion matrix, and handler memoization.
- mount-failure ownership: a throwing enter hook leaves the mounted tree alone;
  first-mount recovery survives a same-turn parent re-render, a superseding
  refresh, and a router-preloaded replacement.
- the virtual-scroll example as an acceptance case: the DOM window stays bounded
  while the backing list does not ([[FEATURE-VIRTUAL-SCROLLING]]).

Gotcha: several suites read compiled fixtures generated by `npm run pretest`
(`npm test` runs it); a bare `npx vitest run` on a fresh clone fails those lanes
until pretest has run once.
