# Todos integration test

The canonical end-to-end runtime proof: a real [[COMPONENT-PUZZLE-APP]] in jsdom,
driven only through public behavior. The suite body is `runTodosSuite` in
`tests/helpers/todos-suite.js`, run in two lanes:

- `tests/todos-app.test.js` — handwritten fixture modules under
  `tests/fixtures/todos/` (`Home`, `Default`, `TodoItem` `.compiled.js`,
  `todo.model.js`);
- `tests/todos-app-compiled.test.js` — modules compiled from
  `examples/todos/app/` by the real Go compiler into
  `tests/fixtures/todos-compiled/` (generated by `npm run pretest`).

Both lanes run the same assertions, keeping runtime behavior and the compiler's
calling convention aligned. The handwritten fixtures are also the codegen golden
reference ([[TEST-COMPILER-CODEGEN]]): change emission and the fixture moves with it.

Coverage: add, special-character text, toggle, filter, keyed DOM identity,
delete, clear-completed, empty state, persistence into a second app instance,
adapter `loadMany` upsert without duplicates, and repeated add/toggle/delete
cycles. `TodoItem` row animations run against the fake WAAPI: enter on add,
removal deferred until the leave animation finishes, no spurious enter/leave on
surviving rows across a filter change, and the fill handback on release.

Gotcha: the suite installs the `/adapter` capability itself, and the test app's
endpoint-backed model means tracked finds fault during mount (D161) — so it stubs
`fetch` with an empty collection and asserts the collection arrives as part of
mount. Tests about server data stub their own `fetch`.
