# Todos integration test

The canonical end-to-end runtime proof: a real [[COMPONENT-PUZZLE-APP]] in jsdom, driven
only through public behavior. The suite body is `runTodosSuite` in
`tests/helpers/todos-suite.js`, run in two lanes with the same assertions:

- `tests/todos-app.test.js` mounts the committed fixtures in `tests/fixtures/todos/`
  (`Home`, `Default`, `TodoItem` `.compiled.js`, `todo.model.js`);
- `tests/todos-app-compiled.test.js` mounts modules compiled from `examples/todos/app/`
  by the real compiler into `tests/fixtures/todos-compiled/` (gitignored, generated by
  `npm run pretest` → `build:example-modules`).

The committed fixtures are also the codegen golden reference
([[TEST-COMPILER-CODEGEN]]): change todos emission and the fixture must move with it, or
Go fails.

Coverage: add, special-character text, toggle, filter, keyed DOM identity, delete,
clear-completed, empty state, persistence into a second app instance, adapter
`loadMany` upsert without duplicates, repeated add/toggle/delete cycles. `TodoItem` row
animations run against the fake WAAPI (`tests/helpers/fake-waapi.js`): enter on add,
removal deferred until the leave finishes, no spurious enter/leave on surviving rows
across a filter change, the fill handback on release.

Gotcha: the suite installs the `/adapter` capability itself, and the endpoint-backed
model means tracked finds fault during mount (D161), so it stubs `fetch` with an empty
collection and asserts the collection arrives as part of mount. Tests about server data
stub their own `fetch`.
